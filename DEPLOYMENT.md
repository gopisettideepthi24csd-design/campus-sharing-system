# Campus Sharing System - Permanent Deployment Guide

This guide explains how to deploy the Campus Sharing System to a permanent hosting platform.

## Deployment Options

### Option 1: Render (Recommended)

Render is a modern cloud platform that makes it easy to deploy FastAPI applications with a free tier.

#### Steps:

1. **Create a GitHub Repository**
   - Go to [GitHub](https://github.com/new)
   - Create a new repository (e.g., `campus-sharing-system`)
   - Clone it locally and push this code to it

2. **Connect to Render**
   - Go to [Render Dashboard](https://dashboard.render.com/)
   - Click "New +" and select "Web Service"
   - Connect your GitHub account and select the repository
   - Configure the following:
     - **Name**: `campus-sharing-system`
     - **Runtime**: `Python 3.11`
     - **Build Command**: `pip install -r backend/requirements.txt`
     - **Start Command**: `cd backend && uvicorn app.main:app --host 0.0.0.0 --port $PORT`
     - **Environment Variables**:
       - `PYTHON_VERSION`: `3.11`
       - `DATABASE_URL`: `sqlite:///./campus_sharing.db`
       - `SECRET_KEY`: (auto-generated by Render)

3. **Add Persistent Storage (Optional)**
   - Render offers a persistent disk for databases
   - Mount it at `/var/data` to persist the SQLite database across deployments

4. **Deploy**
   - Click "Create Web Service"
   - Render will automatically deploy your app
   - You'll get a permanent URL like `https://campus-sharing-system.onrender.com`

### Option 2: Railway

Railway is another excellent platform with a generous free tier.

#### Steps:

1. **Create a GitHub Repository** (same as Render)

2. **Connect to Railway**
   - Go to [Railway Dashboard](https://railway.app/)
   - Click "New Project"
   - Select "Deploy from GitHub"
   - Connect your GitHub account and select the repository

3. **Configure Environment**
   - Railway will auto-detect the Python project
   - Set environment variables:
     - `PYTHON_VERSION`: `3.11`
     - `DATABASE_URL`: `sqlite:///./campus_sharing.db`
     - `SECRET_KEY`: (generate a random string)

4. **Deploy**
   - Railway will automatically deploy
   - You'll get a permanent URL

---

### Option 3: Fly.io

Fly.io is a platform for deploying full-stack applications globally.

#### Steps:

1. **Install Fly CLI**
   ```bash
   curl -L https://fly.io/install.sh | sh
   ```

2. **Create a Fly App**
   ```bash
   fly launch
   ```

3. **Deploy**
   ```bash
   fly deploy
   ```

## Database Persistence

### SQLite (Current)
- The app uses SQLite by default
- The database file is stored at `campus_sharing.db` in the working directory
- For persistent storage on Render, use a persistent disk

### Upgrading to PostgreSQL (Optional)
If you want to use PostgreSQL for better scalability:

1. Update `requirements.txt` to include `psycopg2-binary`
2. Set `DATABASE_URL` to your PostgreSQL connection string
3. The SQLAlchemy ORM will work with PostgreSQL without code changes

## Troubleshooting

### App won't start
- Check the build logs in your hosting platform's dashboard
- Ensure all dependencies in `requirements.txt` are installed
- Verify the start command is correct

### Database errors
- Ensure the database file has write permissions
- For Render, use a persistent disk
- Check that `DATABASE_URL` environment variable is set correctly

### CORS errors
- The backend is configured to accept requests from all origins (`*`)
- This is fine for development; in production, specify exact origins
